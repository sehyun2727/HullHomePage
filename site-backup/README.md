# site-backup/

The complete HULL site as an **All-in-One WP Migration `.wpress`** backup, split into ~90 MB chunks so it fits under GitHub's 100 MB per-file limit. Reassemble → import → done.

---

## What's inside

```
site-backup/
├── parts/
│   ├── hull-site.wpress.part.000    ~90 MB
│   ├── hull-site.wpress.part.001    ~90 MB
│   ├── ...
│   ├── hull-site.wpress.part.015    ~80 MB (last chunk, remainder)
│   └── SHA256SUMS                   per-part integrity checksums
├── wpress-original.sha256           checksum of the reassembled .wpress
└── README.md                        (you are here)
```

Total: **16 parts**, roughly 1.4 GB reassembled.

## Restore procedure

### Step 1 — Verify parts (recommended)

```bash
cd site-backup/parts
sha256sum -c SHA256SUMS
```

Every line should end in `OK`. If any part fails, re-`git pull` and check again.

### Step 2 — Reassemble

Concatenate parts in order into a single `.wpress` file.

**macOS / Linux / Git Bash / WSL:**
```bash
cd site-backup
cat parts/hull-site.wpress.part.* > hull-site.wpress
```

**Windows PowerShell:**
```powershell
cd site-backup
cmd /c "copy /b parts\hull-site.wpress.part.000 + parts\hull-site.wpress.part.001 + parts\hull-site.wpress.part.002 + parts\hull-site.wpress.part.003 + parts\hull-site.wpress.part.004 + parts\hull-site.wpress.part.005 + parts\hull-site.wpress.part.006 + parts\hull-site.wpress.part.007 + parts\hull-site.wpress.part.008 + parts\hull-site.wpress.part.009 + parts\hull-site.wpress.part.010 + parts\hull-site.wpress.part.011 + parts\hull-site.wpress.part.012 + parts\hull-site.wpress.part.013 + parts\hull-site.wpress.part.014 + parts\hull-site.wpress.part.015 hull-site.wpress"
```

(Windows users: installing Git Bash and using the `cat` command is much cleaner.)

### Step 3 — Verify the reassembled file

```bash
cd site-backup
sha256sum -c wpress-original.sha256
```

Should say `hull-site.wpress: OK`. If it fails, one of the parts is corrupted — re-download and try again.

### Step 4 — Import into Local by Flywheel

1. **Install Local by Flywheel** — https://localwp.com/ (free)
2. **Create a new WordPress site**
   - Site name: `hull-homepage-renewal` (matches paths in `CLAUDE.md`; any name works)
   - Environment: Preferred (PHP 8.x, MySQL 8.x)
3. **Open the site** in Local → click **"WP Admin"** (top-right)
4. Log in with the temporary admin created by Local
5. **Install the All-in-One WP Migration plugin**
   - Plugins → Add New → search "All-in-One WP Migration" → Install → Activate
6. Sidebar → **All-in-One WP Migration → Import**
7. **Import from → File → select `hull-site.wpress`**
8. Wait for import (5–15 min depending on machine — the file is 1.4 GB)
9. When prompted, **log in again** using the previous owner's admin credentials (delivered separately, not in this repo)
10. **Settings → Permalinks → Save Changes** (no changes needed — regenerates rewrite rules; without this step `/column/*` and `/works/*` will 404)

### Step 5 — Verify the site renders

Visit each of these routes; every one should render without 404:

- `/`
- `/space/`
- `/vision/` or `/digital-signage/`
- `/sign/`
- `/reform-business/`
- `/philosophy/`
- `/company/`
- `/column/`
- `/works/`
- `/archives/category/news/`

If styles look off, **hard-refresh** (Ctrl+Shift+R). Lightning caches theme CSS via a hardcoded version number.

## If reassembly keeps failing

The **USB handover `.zip`** (built in Phase 11) contains a single, un-split `hull-site.wpress` as insurance. If SHA verification fails repeatedly on the split parts, use the USB copy — it bypasses reassembly entirely.

## Post-import edits

Once the site is up, the child theme lives at:

```
~/Local Sites/hull-homepage-renewal/app/public/wp-content/themes/lightning-child/
```

Compare against `theme-source/lightning-child/` in this repo to see what's been edited over the project's history. When you edit `functions.php`, `style.css`, or any template, copy the changed file back into `theme-source/` in the repo and commit — that keeps the git history honest.

Global page-level CSS lives in **Additional CSS (post 2641)**, edited via wp-admin, not on disk. See `docs/architecture.md`.
